## 节点目标

基于上游完整清理版源稿，由 agent 调用子 agent / subagent 分批完成中文语义编辑、必要翻译、可阅读逐字稿 Markdown 成稿、质量核查和交付整理。最终稿应适合微信公众号或长文阅读，但对话、访谈、播客、演讲和会议类内容必须保留“逐字稿性质”的主体结构，而不是改写成第三人称综述文章。

本节点的核心产出必须由大模型语义处理完成。不得使用脚本、正则、批量替换、本地非语义工具作为正文生成、正文润色、段落改写、讲话人标注、内容压缩或最终成稿的主要方式。脚本只允许用于文件拆分、字数统计、格式检查、路径清单、重复模式辅助检测等非正文创作环节。

## 输入范围

- 上游提供的完整清理版源稿。
- 上游提供的时间映射或分段索引、清理说明和覆盖检查记录。
- 上游提供的字幕、内置转写能力或任务环境可用 ASR/TTS 降级来源说明。
- 若上游采用超长视频分段处理，需读取完整清理版源稿及分段索引，确认合并顺序和覆盖范围。
- 任务需求中对交付形态、讲话人、场合、时间、配图、风格或命名的要求。

## 子 agent / subagent 成稿策略

长内容必须通过调用子 agent / subagent 的方式进行分批语义编辑和撰写，避免主 agent 因长上下文污染、疲劳、遗忘或局部偏差导致质量下降。主 agent 负责制定统一编辑规则、术语表、讲话人表、章节规划、分批边界和最终合并标准；子 agent / subagent 负责在各自批次内完成语义编辑、口水词清理、断句重组、术语核查、讲话人归属判断和可读性润色。

分批处理应按自然章节、演讲人、圆桌问题、议程段落或上游分段索引划分。每个子 agent / subagent 批次必须读取对应上游原文片段和必要上下文，输出可直接合并的编辑稿，并附本批次的不确定项、讲话人归属依据、术语处理和覆盖说明。

主 agent 在最终合并时必须统一标题层级、讲话人标签、术语写法、段落风格和来源说明，检查跨批次重复、遗漏、风格漂移、人名不一致和术语不一致。最终交付必须是一份完整连续的 Markdown 逐字稿。

## 可阅读逐字稿定义

可阅读逐字稿不是原始 ASR 文本，也不是摘要。它应忠实保留信息量、发言顺序、论证链、例子、转折、追问、回答和现场语义，同时由大模型进行中文编辑，使其成为可连续阅读的会议实录、演讲实录、播客实录或访谈实录。

允许为了可读性进行一定程度的扩写，包括补足必要过渡、解释隐含指代、把难懂术语讲清楚、把碎片化口语整理成完整句子、把跳跃表达连接顺畅。扩写必须来自上游源稿已有含义或任务要求，不得替发言人新增观点、事实、数据、情绪、现场反应或结论。

## 讲话人和圆桌处理

- 对话、访谈、播客、演讲和会议类内容：最终稿必须保留逐字稿式主结构，主要内容使用“人名：内容”的格式呈现。
- 多人圆桌或多人讨论必须识别发言轮次，不能把一整段无法确认的多方发言统一归给主持人或上一位发言人。
- 无法确认具体姓名时，使用“未确认发言人 A/B/C”等保守标签，并在处理说明中列出不确定原因和对应章节。
- 可以把同一发言人的连续短句合并成自然段落，但合并后仍需保留对应人名标签。
- 不允许使用“Speaker 1”“Speaker 2”“Speaker”或同类英文泛称作为最终讲话人标签。

## 输出要求

输出完整 Markdown 逐字稿、处理说明、子 agent / subagent 执行记录、术语和讲话人说明、质量核查记录、与上游覆盖关系说明和交付清单。
