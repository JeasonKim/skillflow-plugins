## 节点目标

基于 4.1 完成的完整逐字稿，制作一份精排 HTML 长文。HTML 应是适合网页阅读的深度图文版本，帮助读者快速理解视频或播客的结构、关键观点、论证链和重要例子；它不能替代 4.1 完整逐字稿，也不能把内容压缩成极简摘要或营销海报页。

## 输入范围

- 4.1 输出的完整逐字稿 Markdown。
- 4.1 的处理说明、讲话人姓名来源、术语说明和质量核查记录。
- 上游可用的标题、场合、时间、章节、分段索引或演讲人信息。
- 任务需求中对图文风格、用途、图片数量或发布平台的要求。

## 内容要求

- HTML 应围绕自然章节、报告主题、演讲人、圆桌问题或语义单元组织。
- 每个主要章节应保留讲者身份、核心问题、关键观点、关键例子或数据、与主线的关系。
- 圆桌内容应按问题展开，保留不同嘉宾观点、共识和分歧，不压缩成几个泛泛结论。
- 观点、事实、人名、数据、引用和结论均应可追溯到 4.1 完整逐字稿或上游元信息。
- 对 90 分钟以上或多报告视频，除非任务明确要求极简版，HTML 应保留足够信息量，避免只留下标题级观点。

## 图片和视觉模块

若生成或引用图片，应优先使用任务环境可用的图片生成或绘图能力；不可用时可降级到本地可用工具、手工信息图、HTML/CSS 图表或 Mermaid/结构图。所有图片必须服务于具体章节理解，不得新增逐字稿中无依据的人物、场景、数据、结论或现场细节。

有效视觉模块包括信息图、结构图、流程图、对比图、章节关系图、观点图和必要的解释性配图。纯装饰图、抽象氛围图、无信息结构概念图、机器人摆拍图、假 UI、假仪表盘或未来控制室不计入有效配图。

## 输出要求

输出 HTML 文件、图片资源、图片说明、来源说明、信息量说明、压缩比例说明和工具记录。HTML 应使用相对路径引用本地资源，不依赖私有外部服务才能正常阅读。
