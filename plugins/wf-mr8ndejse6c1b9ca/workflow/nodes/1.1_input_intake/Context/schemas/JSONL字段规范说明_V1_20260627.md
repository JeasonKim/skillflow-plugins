# JSONL 字段规范说明 V1 20260627

本目录用于固定 1.1 Context 内三个 JSONL 状态文件的字段，避免后续 agent 写出不同字段名，导致查重、筛选和 Markdown 看板同步失效。

## 通用规则

- 每一行必须是一个完整 JSON 对象。
- 字段名使用 camelCase，不使用 snake_case。
- 字段缺失时优先写空字符串 `""`；确实无法判断的状态值写 `unknown`。
- 不伪造链接、标题、发布日期、节目归属或处理状态。
- URL 字段必须写可直接打开的完整 URL。
- 日期字段优先使用 `YYYY-MM-DD`；需要精确时间时使用 ISO 8601。

## processed_video_log.jsonl

用途：记录已经处理过的视频或播客单集，用于查重和历史追踪。

配套 schema：

- `processed_video_log.schema_V1_20260627.json`

关键字段：

- `canonicalKey`：查重主键，必须尽量稳定。示例：`youtube:VIDEO_ID`、`bilibili:BV_ID`、`podcast:PodcastName:EpisodeId`。
- `status`：建议值为 `completed`、`partial`、`failed`、`skipped`、`blocked`、`unknown`。
- `podcastMatched`：建议值为 `yes`、`no`、`unknown`。
- `markdownOutput`、`htmlOutput`、`pdfOutput`、`epubOutput`：写本地输出路径；没有则留空。

## podcast_episode_backlog.jsonl

用途：记录已经发现但尚未创建 task 或尚未处理的候选播客单集。

配套 schema：

- `podcast_episode_backlog.schema_V1_20260627.json`

关键字段：

- `canonicalKey`：候选查重主键，优先用平台稳定 ID。
- `status`：建议值为 `todo`、`processed`、`skipped`、`uncertain`。
- `priority`：建议值为 `high`、`medium`、`low` 或空字符串。
- `sourceConfidence`：建议值为 `high`、`medium`、`low`、`unknown`。
- `matchedProcessedTaskCode`：如果发现已处理记录，写对应 taskCode；否则留空。

## podcast_watch_sources.jsonl

用途：记录每档关注播客应该去哪检查更新。

配套 schema：

- `podcast_watch_sources.schema_V1_20260627.json`

关键字段：

- `officialSiteUrl`：节目官网、机构节目页、主持人节目页或官方承载页。
- `rssUrl`：可机器读取的 podcast RSS feed。
- `appleUrl`：Apple Podcasts 节目页。
- `youtubeChannelUrl`：官方频道、母频道或节目承载频道。
- `youtubePlaylistUrl`：节目 playlist；没有则留空。
- `status`：建议值为 `verified`、`partial`、`unverified`、`retired`。

## 维护建议

- JSONL 作为机器主数据。
- Markdown 看板应从 JSONL 同步，或者至少与 JSONL 保持字段含义一致。
- 如果新增字段，先更新本说明和对应 schema，再更新数据文件。
